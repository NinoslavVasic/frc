# moonshot-properties.nyc: audit, 10/16/2026

Scope: the v6 site in `NinoslavVasic/frc` (main), checked against the demand letter Piece of Cake received (Marin v. Piece of Cake Moving + Storage LLC, 05/20/2026). This is a technical review, not legal advice. Have counsel confirm before relying on it.

## 1. Tracking and privacy (the Piece of Cake issue)

**What the letter alleges against Piece of Cake.** Its site (mypieceofcakemove.com) loaded Meta and TikTok tracking pixels on arrival, which sent visitors' IP address, page URL, referrer, device identifiers and cookies to those companies with no disclosure and no consent. The claims: CIPA pen register / trap and trace (Cal. Penal Code § 638.51), federal Wiretap Act, CDAFA, intrusion upon seclusion, unjust enrichment.

**Moonshot's site, as live today (v6):**

| Check | Result |
|---|---|
| Meta, TikTok, Google, LinkedIn or other ad pixels | None |
| Analytics (Google Analytics, Tag Manager, etc.) | None |
| Cookies | None set |
| Session recording, chat widgets, social embeds | None |
| Third-party requests on page load | **Google Fonts** (fonts.googleapis.com, fonts.gstatic.com) receives every visitor's IP, browser and referring origin |
| Third-party requests on user action | unpkg (map code) and Esri (map images) when the street map is opened; Web3Forms when the form is sent |
| Privacy notice | None |

**Assessment.** None of the conduct named in the letter (ad pixels, profiling, cross-context advertising) happens on this site. The one automatic third-party request is Google Fonts, which is a font download, not a tracking pixel. It is still an automatic transfer of IP and referrer to Google, and plaintiffs' firms scan sites for any third-party call. Removing it costs nothing.

**Law update.** California SB 690 was signed 09/30/2026 and takes effect 01/01/2027. From then on, website pen-register / trap-and-trace claims under § 638.51 can be brought only by the California Attorney General, not by private plaintiffs. It applies retroactively to claims in actions filed on or after 01/01/2025. It does **not** affect CIPA wiretap (§ 631), the federal Wiretap Act or CDAFA claims. The Piece of Cake letter's § 638.51 theory may be weakened, but its other counts are not. Piece of Cake should take this to its counsel.

**Fixed in v6.1 (ready in `deploy/`):**
- Fonts and map code are now served from moonshot-properties.nyc. On first load the page contacts **no third party at all**.
- Esri map images load only when a visitor opens the street map, with a note beside the map.
- New `privacy.html`: no cookies, no analytics, no pixels; what the form collects and who delivers it (Web3Forms); hosting logs (GitHub); Esri on demand; links to LoopNet and others; how to ask for deletion. Linked from the form, the map and the footer.
- Footer line: "No cookies, no tracking".

**Disclaimer or cookie banner?** Not needed now. A banner asks consent for tracking; this site has none. The privacy notice is the right disclosure. **If anyone adds analytics, a Meta/LinkedIn pixel, Google Tag Manager, a chat widget or an embedded video later, a consent banner must be added first, and the tag must not fire until the visitor agrees.** Write this into the README so it is not forgotten.

## 2. Security

| Item | Status | Action |
|---|---|---|
| HTTPS, Enforce HTTPS | On (GitHub Pages) | None |
| Content-Security-Policy | Meta tag; allowed inline scripts and Google, unpkg | **Tightened in v6.1:** `script-src 'self'` only (script moved to `js/site.js`); fonts and styles from self; images from self + Esri; connect to Web3Forms only |
| Third-party script supply chain | Leaflet from unpkg with SRI | **v6.1:** served from this site; no third-party script at all |
| Clickjacking (`frame-ancestors`, X-Frame-Options) | **Not active.** GitHub Pages cannot send headers; a meta tag cannot set these | Put Cloudflare (free plan) in front, or move to Cloudflare Pages or Netlify, which read `_headers` directly |
| HSTS | Sent by GitHub Pages once Enforce HTTPS is on | `_headers` no longer asks for `preload`; don't submit to the preload list |
| Form spam / abuse | Honeypot + validation; Web3Forms key is public by design | In the Web3Forms dashboard, restrict the key to `www.moonshot-properties.nyc` and turn on its spam filter |
| Email spoofing (someone sending as @moonshot-properties.nyc) | Not checked: DNS is outside the repo | Confirm SPF, DKIM and a DMARC record (start with `p=quarantine`) at the registrar |
| security.txt | Present, expires 2027-09-02 | Renew before then |
| Exposed secrets in repo | None found | None |
| External links | `rel="noopener"` on all | None |
| Leftover files | `robots.txt` named two removed pages | Cleaned in v6.1 |

**Should security be tightened?** Yes, three steps, in order of value:
1. Upload v6.1 (no third-party code, strict script policy).
2. Restrict the Web3Forms key to your domain.
3. Put Cloudflare in front of GitHub Pages to get clickjacking protection and the rest of `_headers`. Optional, but it is the only remaining gap.
